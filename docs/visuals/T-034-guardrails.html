Guardrails · T-034 · 2026-11-22

What must stay true while we build

The technical decisions are now written as seven contracts and twenty-four guardrails. Each guardrail is one sentence you can check against what you decided, and each names the test that will fail if the sentence stops being true.

Needs you

Do you recognise your decisions in these sentences? Say which to change, drop or add. All but one are "pending": the product has no code yet, so their tests are named but not written. The first build task that touches one writes its test first and sees it fail.

The seven contracts

Each says who calls whom, what is sent (with one real example), what is promised, what happens on failure, how it may change, and which guardrails hold it.

BoundaryIn one lineFile
Screen → ConversationsEvery action carries an ID; "saved" means saved and logged; the same ID again changes nothing.screen-to-conversations.md
Conversations → ScreenNumbered updates; after any gap the screen says its number and gets the rest, or reloads.conversations-to-screen.md
Conversations → SearchWhole message with a version; never lost, may repeat; newest version wins, delete wins.conversations-to-search.md
Conversations → Activity feedEvery change, strictly in order; a change the feed cannot apply is fenced.conversations-to-feed.md
